# Velisa: which skill to use

**Called by name.** When the user starts with "Velisa" (or ベリサ / ヴェリサ), treat the rest as a production request: if it names media and a goal, route it as below; if it is vague ("Velisa, make this nicer"), ask once for the input file and the delivery (where it will be shown, length, language), then route.

Every OS skill also works on its own, so any of them may be missing. Decide per task, in this order, and tell the user which level you used.

1. **An OS skill is installed for this job** (table below): use it. For a whole production (several steps, approval, a delivery target) use `video-production-agent`, which plans with every installed skill and reports the ones it cannot reach.
2. **No OS skill for this job here**: use another skill that is installed, or a standard tool already on the machine (for example ffmpeg / ffprobe). Say that this step is outside the OS: no contract, no provenance record, no OS QA.
3. **Nothing installed fits**: do it yourself only if it is safe to do with the tools you have, explain exactly what you did, and verify the output (play / probe it, or `video-agent check` when the agent is installed). Otherwise stop and name the skill that would do it.

At levels 2 and 3, say which OS skill would cover the job and how to add it: `/plugin install <skill>@velisa` in Claude Code, or `./install.sh` from Velisa for everything (CLIs, Python packages, Codex skills).

Never claim a result is verified, measured or approved unless a skill or the agent reported it. A measurement that is missing is unknown, not zero.

## Production steps and review

For any job that writes media: probe the inputs, show the plan (`--dry-run --json`) and what a dry run does not check, trial a long job on a short excerpt and run the full encode in the background, then compare the probed result with the request yourself. A tool's `verified: true` is not that comparison; `unverified` items are unknown. End with a review list that separates what a tool checked from where a person must look or listen. Steps and checkpoints: [review.md](review.md). For a production with several stages (transcript, rough cut, picture, captions, graphics, sound), follow the default stage order and go through the before-export list in [stages.md](stages.md); a passed check is not an acceptance of the finished piece.
